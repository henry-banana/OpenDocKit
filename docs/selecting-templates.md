# Selecting and copying templates

## Choose a representation

Minimal keeps current concerns together in files; comprehensive separates them
into focused concern folders. Both include optional repeatable records. Choose
based on reader, owner and update needs, not a company-size label. An individual
concern can expand later without moving every other document.

## Copy into the recipient

Browse [INDEX](../INDEX.md) and copy paths below `templates/minimal/` or
`templates/comprehensive/` into the project root. Project-specific and agent
samples are inside those same roots. The wrapper directories and library guides
stay in OpenDocKit. Select files or copy a representation and remove unneeded
parts before adoption; inspect existing README/license/settings before merging.

Copy a concern's linked dependencies or adapt its links to the recipient's real
sources. Optional license alternatives need an explicit choice and correct
notices; the supplied names do not automatically set the recipient's license.

## Fill and maintain

Use the author guidance, then remove it after filling actual scope, owners,
constraints, evidence and unknowns. Link shared authority instead of duplicating
mutable tracker/code/contract facts. Maintain current knowledge and active work
records; preserve closed records with explicit corrections or successors.

For expansion, see [manual migration](migrating-documentation.md). For personal
agent work, set the [actual storage and Git policy](workspace-and-retention.md)
before use. Copies are owned and maintained by the adopting team.
