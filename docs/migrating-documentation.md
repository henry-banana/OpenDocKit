# Manual migration and concern expansion

## Moving from an earlier source layout

All copyable material now lives beneath `templates/minimal/` or
`templates/comprehensive/`. Earlier sibling specialty/workspace shelves and the
catalog are retired. Use the actual [index](../INDEX.md) to locate successors;
[the historical migration map](migration-map.json) records a previous snapshot,
not the current inventory.

For an adopted project, compare useful new content with its existing authority,
merge deliberately and repair links. The library does not replace or update an
existing docs/config tree. Review native settings and license notices separately.

## Expand one concern

1. Identify which reader, ownership or update needs make a combined document hard
   to maintain.
2. Map its facts, constraints, unknowns and evidence to focused successor files.
3. Preserve significant decisions as ADRs and keep one authority for current facts.
4. Repair incoming paths/anchors or retain a concise successor navigation page.
5. Review the result and remove competing complete current descriptions.

Other concerns may remain minimal. Role briefs and agent routes should follow the
actual adopted successor paths. Shared specs/plans/tasks/reviews have explicit
record identities under docs; personal continuity follows the selected storage
policy rather than a mandatory change directory.
