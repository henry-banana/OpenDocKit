# Authoring contract

[CONTRIBUTING](../CONTRIBUTING.md#author-templates) defines current authoring and
placement rules. Read the nearest existing source before adding another document.

Each sample serves a specific reader task with a purpose, use trigger, scope
boundary and observable completion criteria. Split when ownership, reader need or
update rhythm earns separate maintenance; concise documents still preserve
constraints, evidence and unknowns.

Documentation samples carry unique author-guidance IDs and copy-relative
suggested destinations. Use meaningful filling prompts and completion checks.
Native configuration, machine-readable contracts and standard license text retain
their actual format; they are not forced into Markdown metadata/checklists.

Copy roots mirror recipient projects. Keep internal links inside the selected
representation or make project-specific links explicit filling prompts. Library
navigation stays in root INDEX; recipient READMEs describe the adopted project.
Shared root boilerplate is authored in comprehensive and mirrored in minimal;
concern content is deliberately written for its respective representation.

Review usefulness, overlap, factual claims, citations/reuse terms and actual copy
behavior. Keep source paths, destinations, index entries and affected guidance in
sync; use the [maintainer checks](maintenance.md). Native provenance/client loading
requires explicit evidence in associated guidance or review, not a second catalog.
